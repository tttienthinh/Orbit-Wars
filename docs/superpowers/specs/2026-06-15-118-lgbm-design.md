# 118-LGBM: LightGBM Attack Prediction Baseline

**Date:** 2026-06-15  
**File:** `118-LGBM.py`  
**Purpose:** Flat-feature LightGBM benchmark for binary attack prediction (will this src→tgt pair be attacked?), enabling direct AUC comparison against the GNN in 117.

---

## Context

117-NewGNN.py trains a heterogeneous GNN on the same prediction task. 118-LGBM.py provides a strong tabular baseline using the same precomputed data (`114-precompute/`) and the same train/test episode split logic.

Key facts from data exploration:
- 542 episodes, IDs ~78M (higher ID = harder opponent)
- ~499 game steps per episode have reach edges
- Max travel time = 20 steps (= `NB_STEPS_SIM`) — all arrivals are within t+20
- ~5.4M total (src, tgt, step) pairs across all episodes

---

## Data Sources

Same as 117 — one subdirectory per episode under `114-precompute/`:

| File | Columns | Notes |
|---|---|---|
| `df_s.parquet` | id, step, x, y, ships, owner, production, nature | Planet state at each game step |
| `reach.parquet` | id_src, step_src, id, step, ships_sent | Reach edges; ships_sent ∈ {1,2,4,8,…,1024}; step = arrival step |
| `actions.parquet` | game_step, id_src, angle, ships_sent, id | Actual attacks (positive labels) |

## Feature Vector (95 features per pair)

Each training row corresponds to one (src_planet, tgt_planet, game_step_t) tuple where `src_planet.owner == 0`.

### Source features at step t (12)
| Feature | Formula |
|---|---|
| `src_x` | x / 100 |
| `src_y` | y / 100 |
| `src_ships` | log(max(ships, 1)) / log(1024) |
| `src_is_fix` | nature == "fix" |
| `src_is_moving` | nature == "moving" |
| `src_is_comet` | nature == "comet" |
| `src_production` | production / 5 |
| `src_owner_{-1,0,1,2,3}` | one-hot (always 0 for source by construction) |

### Target features at step t (12)
Same 12 features with `tgt_` prefix. `tgt_owner` will vary (neutral, opponent, etc.).

### Travel time features (11)
For each `ships_sent` in `[1, 2, 4, 8, 16, 32, 64, 128, 256, 512, 1024]`:
- `travel_{ships_sent}` = `(arrival_step − t) / 20`
- `NaN` if no reach edge exists for that (src, tgt, ships_sent) combination

### Target trajectory features (40)
For `offset` in `0..19` (covering the full travel horizon):
- `tgt_ships_t{offset}` = `log(max(ships, 1)) / log(1024)` at step `t + offset`
- `tgt_owner_t{offset}` = raw owner value at step `t + offset`
- Fill with `0.0` / `-2.0` (sentinel) if step not present in `df_s`

### Source trajectory features (20)
For `offset` in `0..19`:
- `src_ships_t{offset}` = `log(max(ships, 1)) / log(1024)` at step `t + offset`
- Fill with `0.0` if step not present in `df_s`
- Captures production accrual and incoming friendly fleets on the source planet

## Episode Split

```python
ep_ids = sorted([int(d.name) for d in PRECOMPUTE_DIR.iterdir() if d.is_dir()])
random.seed(42)
random.shuffle(ep_ids)          # mix easy (low ID) and hard (high ID) in both sets
split = int(TRAIN_RATIO * len(ep_ids))   # TRAIN_RATIO = 0.8
train_ids = set(ep_ids[:split])
test_ids  = set(ep_ids[split:])
```

**Why shuffle:** episode IDs correlate with difficulty (lower = weaker opponents). Pure head/tail split would train only on easy games and test only on hard games — misleading AUC.
